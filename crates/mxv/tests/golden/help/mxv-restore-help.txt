Rebuild an archived workspace at its archived commits.

When a workspace already has the name and no archive of it needs restoring, mxv changes nothing and the result's state is unchanged. When an earlier restore stopped after it rebuilt the workspace and before it deleted the archive, so the archive has the workspace's stable id, and the workspace's directory and every checkout's directory are there, mxv asks and then deletes the archive with its pins, because the workspace holds every commit again, and the state is still unchanged. When one of those directories is gone, the archive may hold the only copies of the workspace's files, so mxv keeps it and refuses with mxv::restore::name_taken; `mxv remove NAME` removes what is left of the workspace, and a restore then brings it back.

Usage: mxv restore [OPTIONS] <NAME>

Arguments:
  <NAME>
          The name of the archived workspace

Options:
      --force
          Restore without the ignored files whose copy in the archive is missing or damaged, and list them as lost

      --dry-run
          Report what the command would change, and change nothing

      --yes
          Proceed without asking for confirmation

      --json
          Print the result as a JSON document. The default prints text.

      --no-input
          Fail instead of asking a question

  -h, --help
          Print help (see a summary with '-h')

Examples:
  mxv restore sample --dry-run
          Print what restoring the archived workspace sample would do

Effects: additive, idempotent, open-world.
