Run a one-off command in a workspace or in the context of a running unit, and exit with its exit code.

With no UNIT, the command runs on the host in the workspace, and it needs no running unit and no mxv.toml. It runs at the top of the checkout that --repo names; or else in the current directory when that is inside a checkout; or else at the top of a workspace's only checkout; or else in the workspace's directory. It receives what a mise task of `mxv run` receives: the workspace's ports as MXV_PORT_<NAME>, with those of the checkout it runs in short and the others as MXV_PORT_<CHECKOUT>_<NAME>, the variables of every service that the manifest declares, and the variables that a host process receives from your environment. A variable outside that list does not reach the command, so write `mxv exec -- env NAME=value COMMAND` to set one. mxv starts no services and no units, so run `mxv up` first when the command talks to them. The command has no sandbox and no time limit. It takes one place from deadband, and --no-gate asks deadband nothing. Run `mxv exec -- cargo test` rather than `deadband run -- mxv exec -- cargo test`, because a job that deadband already admitted gets no thread limits for the command. A Ctrl-C at a terminal reaches the command itself, and mxv waits for it to end. mxv holds the workspace's lock only until the command starts, so `mxv up` and `mxv down` still work, and `mxv down` does not stop the command. `mxv remove` and `mxv archive` do not wait for the command, so end it before you run them.

With a UNIT, a host process's command runs in the process's directory, with the variables that the process receives and under its sandbox, as `mxv up` starts the process. A container's command runs inside the container through `docker exec`, with a terminal of its own when mxv's standard input and output are both terminals. The command is the words after `--`, which no shell reads. mxv exits with the command's exit code, or with 128 plus the number of the signal that ended it. A sandboxed command exits with 78 when its sandbox cannot be applied. A sandboxed command runs in a session of its own and cannot have the terminal, so mxv refuses it while its standard input, output or error is a terminal, and on Ctrl-C mxv stops the command's process group. The command keeps running when something sends SIGTERM to mxv alone. A host command is not one of the workspace's processes, so `mxv down` does not stop it.

Usage: mxv exec [OPTIONS] [UNIT] -- <COMMAND>...

Arguments:
  [UNIT]
          The running unit in whose context the command runs, which defaults to running it on the host in the workspace

  <COMMAND>...
          The command's program and its arguments, after `--`

Options:
  -w, --workspace <WORKSPACE>
          The workspace, which defaults to the one that holds the current directory

      --repo <CHECKOUT>
          The folder of the checkout to run the command at the top of, when the command line names no UNIT

      --no-gate
          Ask deadband for no place, when the command line names no UNIT

      --json
          Print the result as a JSON document. The default prints text.

      --fields <FIELD>
          Print only these comma-separated fields, in this order. The default prints the compact columns.

      --long
          Add the long columns after the compact ones. The default prints only the compact columns.

      --full
          With --json, print every field of every row. The default prints only the fields of the columns.

      --no-input
          Fail instead of asking a question

  -h, --help
          Print help (see a summary with '-h')

Examples:
  mxv exec -w reading-list web -- env
          Print the variables that a command receives in the context of web

  mxv exec -w reading-list -- env
          Print the variables that a command receives in the workspace, with no unit running

Effects: destructive, not idempotent, open-world.
Writes: applies all items or none.
Exit code: the command passes on the exit code of the command.
