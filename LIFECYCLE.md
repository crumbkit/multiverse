# Lifecycle

This document lists each state that multiverse keeps across commands, across the crates `mxv`, `multiverse` and `phase`. It covers state enums that are stored, and lifecycles that exist only as a layout on disk. It describes the code at this commit.

File paths are relative to `crates/`.

Each table has these columns:

- **Transition** names the states before and after, and the event that moves them.
- **Owner** names the function that performs the transition and its file.
- **Crash point** says where a process death, a kill or a failed step can happen.
- **State left** says what that crash leaves on disk or in the process table.
- **Recovery** says what the next command does, or says that nothing recovers it.
- **Fault test** names a test that causes that fault and then checks the outcome, with its file. The cell says whether the test kills a process, fails a step through a seam, or plants the state and kills nothing. "None" means no such test exists.

Writes to records use `store::replace_file` (`multiverse/src/store.rs`), which writes a temporary file, syncs it, renames it over the target and syncs the directory. A crash during that call leaves the old record or the new one. Locks are `flock` locks, which the operating system releases when the holder dies, so a crash leaves no lock held.

A workspace record is created only by `Store::create`. `Store::update` reads the record before it writes, writes nothing when the record on disk holds another state than the command read (`Error::StateChanged`, see [Workspace creation](#workspace-creation)), and checks that the record exists, and returns `Error::RecordMissing`, which mxv reports as `mxv::workspace::not_found`, when it does not, so a command that read the record before another command deleted it cannot write it back. `Context::lock` (`mxv/src/processes.rs`) reads the record again once it holds the workspace lock and fails with `mxv::workspace::not_found` when it is gone, before the command writes, starts or stops anything. This covers `up`, `down`, `restart`, `ports reset`, `pin`, `unpin`, `exec` and `run`. The check in `Store::update` and the rename are two steps: an archive deletes the record under the workspace lock, so a writer that holds the lock is safe, while `mxv remove` deletes the record without the lock, and a record that it deletes between the check and the rename is still written back.

| --- | --- | --- | --- | --- | --- |
| Absent stays absent, at a write | `Store::update` (`multiverse/src/store.rs`) | None. It writes no temporary file. | No record. | `mxv list`. | `a_store_does_not_write_back_a_record_that_was_deleted` in `multiverse/src/store/tests.rs` plants the state and kills nothing. |
| Absent stays absent, after a wait for the workspace lock | `Context::lock` (`mxv/src/processes.rs`) | None. The command has written nothing and started nothing. | No record. The lock is released when the command exits. | `mxv list`, then `mxv restore <name>` when the workspace was archived. | `a_pin_that_waited_for_the_lock_fails_and_writes_no_record_when_the_record_was_deleted` and `an_up_that_waited_for_the_lock_starts_nothing_when_the_record_was_deleted` in `mxv/tests/processes.rs` delete the record while the command waits and kill nothing. |

## Workspace creation

The workspace record at `$XDG_STATE_HOME/mxv/workspaces/<name>.json` stores the workspace's state, `WorkspaceState` (`multiverse/src/record.rs`): `creating` from the record's first write until the last write of `mxv new`, `live` after it, and `retiring` with an archive id once `mxv archive` starts, as the table "Archiving a workspace" says. `Store::create` writes the record as `creating`, and `Store::advance` (`multiverse/src/store.rs`) moves it to `live` as the last write of `Workspaces::make` and `make_clones`. `Store::advance` permits `creating` to `live`, `live` to `retiring`, and `retiring` to `retiring` into the same archive, which writes nothing. It refuses any other move with `Error::TransitionRefused`. `Store::repoint` moves a `retiring` record to another archive id and refuses any other state. `Store::update` never changes the state, and writes nothing when the record on disk holds another state than the one the command read, returning `Error::StateChanged`, which mxv reports as `mxv::workspace::state_changed`. A record that an older mxv wrote has no `state` key: it reads as `creating` when it is a workspace of clones whose checkouts all lack a commit, and as `live` otherwise, and never as `retiring`. `Store::update` gives a record without a stable id one, except while a version 2 `Retiring` archive without a workspace id, or an archive record that cannot be read, holds the name (`archive::mint_held`, `multiverse/src/archive/record.rs`). `phased::saved_workspace_id` (`multiverse/src/runs/phased.rs`) then refuses `up`, `restart` and `run` with `Error::ArchiveUnfinished` (`mxv::workspace::archive_unfinished`) before anything starts. A checkout with `commit: null` beside checkouts with commits is a checkout that an `mxv add` left unfinished (`Workspace::is_unfinished`), and the workspace stays `live`.

States are absent, `creating` with no commits, `creating` while cloning, and `live`.

A `creating` workspace is refused with `mxv::workspace::creating` by `up`, `restart`, `ports reset`, `run`, `exec` and `pin` (`Context::lock_live`, `mxv/src/processes.rs`), by `run`, `exec` and `clean` before the lock (`processes::refuse_unfinished`), by `add` (`AddOutcome::Creating`) and by `archive` (`ArchiveRefusal::Creating`, `multiverse/src/archive/admit.rs`). `mxv reclaim` keeps it with a reason (`processes::reclaim_stop`). `down`, `status`, `show`, `logs` and `remove` work on it.

Only the library reaches the two `Workspaces::make` rows below. mxv always calls `with_mirrors` (`mxv/src/verbs.rs`), so `create_repos` returns through `create_clone`. A worktree workspace reaches mxv only as a version 1 record or a restored worktree archive.

## Workspace marker

mxv keeps an empty regular file named `.deadband-workspace`, with mode 0644, in each workspace's directory (`multiverse/src/marker.rs`). deadband walks up from a job's directory to the nearest directory that holds a regular file of that name and shows that directory's name as the job's workspace, so a job that a person runs by hand in a checkout, such as `deadband run -- cargo test`, shows its workspace. Every build and task that mxv itself admits names its workspace in `Asked.workspace` (`multiverse/src/runs/phased/build.rs`, `mxv/src/admission.rs`), so mxv's own jobs do not depend on the marker.

The marker has no stored state. Each verb reads the directory. Its states are absent, present (a regular file of the name) and blocked (an entry of the name that is not a regular file, such as a directory or a link). mxv never replaces an entry of the name, and it deletes only an empty regular file. `.deadband-workspace` is in `RESERVED_FOLDERS` (`multiverse/src/workspaces.rs`), so no checkout's folder can take the name.

## Removing a workspace

`RemovalPlan` and `RemovalOutcome` are per-call results. The state is the record, the checkouts, and the names `.<folder>.mxv-removing` that hold a checkout during its deletion.

`mxv remove` (`verbs::remove`, `mxv/src/verbs.rs`) calls `stop_all`, which takes and releases the workspace lock, and then calls `Workspaces::remove` with no workspace lock held. A concurrent `mxv up` can therefore start between the stop and the removal. `Workspaces::remove` replans first and returns `RemovalOutcome::Changed` when `loses_more` finds a worse plan.

## Archiving a workspace

`ArchiveState` (`multiverse/src/archive/record.rs`) has the states `Retiring`, `Retired` and `Archived`, and is stored in `$XDG_STATE_HOME/mxv/archives/<name>/archive.json` at version 3. `Workspaces::archive` (`multiverse/src/archive/retire.rs`) moves the workspace record to `retiring` with the archive's id, then writes the archive record `Retiring`, and writes it `Retired` once every checkout is retired, before it removes the workspace record. `Workspaces::finish_archive` in the same file is the only function that writes `Archived`. The archive's id is the id of the archive record when one exists, else the id that the workspace's state names, else a new one. A record of version 2, which an older mxv wrote, has no `Retired`, so a `Retiring` one counts as retired wherever no workspace of the same identity exists (`Archive::counts_as_retired`). Same identity means that the workspace state is `retiring` into the archive's id, that both records hold equal workspace ids, or that the archive is version 2 and neither record holds one (`health::same_workspace`). `health::archive_case` (`multiverse/src/health.rs`) is the one rule that reads an archive record beside the workspace record of its name, and `health::classify` for `mxv list`, `Workspaces::subject` (`multiverse/src/archive/admit.rs`) for `mxv archive` and `Workspaces::repair` (`multiverse/src/health/repair.rs`) for `mxv repair` each take their answer from it. With no workspace record, an unfinished archive is `ArchiveCase::Renaming` when it is one of the two records of a rename that a repair stopped (`ArchiveRefusal::RenameUnfinished`). Otherwise a version 3 `Retiring` one is `ArchiveCase::WorkspaceRemoved` (`ArchiveRefusal::WorkspaceRemoved`), and one that counts as retired is `ArchiveCase::Finishable` (`ArchivePlanned::Finish`) unless the head pin of any checkout no longer names its commit, when it is `ArchiveCase::PinsGone` (`ArchiveRefusal::PinsGone`). The other pins are not checked. The three readers give different answers in three places. First, when a pin cannot be read, `Workspaces::subject` fails, so `mxv archive -w` never finishes an archive whose pins may be gone, while `mxv list` and `mxv repair` count the pin as there and name `mxv archive -w`. Second, for a stopped rename whose old name a newer workspace holds, `mxv list` shows `rename_unfinished`, while `mxv archive` of that name refuses with `name_taken`. Third, for an archive that counts as retired beside a newer workspace, `mxv list` names `mxv repair`, while `Workspaces::repair` reads the pins with `health::pins_gone` and fails with the error of a pin it cannot read. `the_listings_the_archive_command_and_the_repair_read_every_pair_of_records_as_the_table_says` in `multiverse/src/archive/tests/cases.rs` checks the three answers for every pair of records, the first two differences included.

The `Err` of the `checkpoint` seam stops `Workspaces::archive` and runs no undo, so the two tests below leave the state that a kill at that point would leave. They name the step labels in the table. They are `a_worktree_archive_stopped_after_each_step_finishes_when_it_runs_again` and `a_clone_archive_stopped_after_each_step_finishes_when_it_runs_again` in `multiverse/src/archive/tests.rs`. ## Deleting an archive

## Repairing an archive

`repair::repair` (`mxv/src/repair.rs`) takes the lock of the name, or for a stopped rename the locks of both names in sorted order, and calls `Workspaces::repair` (`multiverse/src/health/repair.rs`), which classifies the records of that one name with `health::archive_case` and repairs the problems whose repair is `mxv repair <name>`. Before it reads a single name, `Workspaces::repair` reads every archive record and looks for a rename that an earlier repair stopped, through `health::rename_pair`, and finishes it whichever of the two names it was given. When the archive record of the name cannot be read, `Workspaces::repair` returns the read error. A dry run takes no lock and changes nothing. A change asks first, plans again under the lock, and refuses with `mxv::repair::changed` when the new plan would ask a different question. ## Sweeping what no record names

`repair::orphans` (`mxv/src/repair.rs`) calls `Workspaces::orphans` (`multiverse/src/health/orphans.rs`), which lists these kinds of item with their sizes:

- the run files `$XDG_STATE_HOME/mxv/runs/<name>` of a name that no workspace record has and no unfinished archive has, when the directory holds more than the lock file that any command of the name leaves (`Runs::run_dirs`, `multiverse/src/runs/phased.rs`);
- phase's run record `phase/runs/<id>.json` and logs `phase/logs/<id>`, and with `--delete-volumes` the docker data volumes, of a workspace id that no workspace record and no archive record holds, a moved-aside one included (`Runs::phase_ids`, `Runs::volume_ids`). An id may have only volumes, such as one that a removal stopped after it forgot the id leaves; its item's path is then the first volume's name. One `docker volume ls` lists the volumes by their workspace-id label, and only the volumes whose run-record label names this state directory's phase count, so the volumes of another state directory that shares the docker daemon are never listed. Without `--delete-volumes` the listing asks docker nothing, and with it a docker that does not answer fails the listing before anything is deleted, run files included;
- each archive that a repair moved aside to `.<name>.<id>`;
- each data directory `$XDG_DATA_HOME/mxv/archives/<id>` whose id no archive record names;
- each directory of the archives without its own record: a hidden one that holds no record or another archive's record, and one of a name that holds no record, such as the directory that a running archive makes before it writes its record (`Archives::leftovers`, `multiverse/src/archive/record.rs`).

It reads these directories before the records. Each command that makes such a thing writes its record first, except a command that holds the lock of the name, which the sweep of run files takes. When a workspace or archive record cannot be read, a moved-aside one included, `orphans` returns that record's read error, mxv exits with its code, and nothing is listed or deleted, because the record may name what looks orphaned. The listing and `--dry-run` take no lock and write nothing.

Run files and run records are mxv's and phase's derived state, so `--orphans` deletes them after the person confirms or passes `--yes`. Before a run record is deleted, phase's sweep (`Runs::forget_id`) stops the processes and removes the containers, networks and run volumes that it names. The volumes that hold the workspace's data stay unless the person passes `--delete-volumes`, which deletes the volumes that docker labels with the id. `Runs::forget_id` deletes those volumes before the logs, so when docker fails the logs stay and the next sweep lists the id again. A moved-aside archive and a data directory hold the only copies of their files, so only `--delete-aside` deletes them, and `--yes` only skips the question. A directory of the archives without its own record is never deleted; its row says why.

`Workspaces::sweep_orphan` takes the lock of the name of run files, then lists again without measuring sizes, and deletes one item only when the new listing still holds it: the same kind at the same path, or a run record of the same id. Only the second listing for a run record asks docker. A directory of the archives without its own record is kept before the second listing, since it is never deleted. `Runs::forget`, which `mxv remove` and `mxv archive` call, forgets the id through `Runs::forget_id` as well. When phase keeps the run record, `mxv remove` and `mxv archive` report each reason as a warning and finish.

## Mirrors

A mirror has no state enum. It is a bare repository at `$XDG_DATA_HOME/mxv/mirrors/<origin key>`, guarded by `<mirror>.lock` (`Workspaces::lock_mirror`, `multiverse/src/workspaces.rs`). States are absent, prepared and fetched.

## Run records and process entries

`EntryState` (`phase/src/record/run.rs`) has the states `Planned`, `Running`, `Stopping` and `Stopped`. phase stores it for each keeper, host process, container, network and volume in `$XDG_STATE_HOME/mxv/phase/runs/<id>.json`, and writes each state before the step that the next state describes. A host entry also stores `completed`, which the oneshot table below covers. `Journal` (`phase/src/record/store.rs`) performs every write under the lifecycle lock.

Two writers own host entry states. The engine owns them during `up`, `restart` and `down`, through `Journal`. The keeper's `Recorder` (`phase/src/engine/keeper/recorder.rs`) owns them afterwards and writes them asynchronously, so a restart or an end can change an entry at any time. A `Recorder` note applies only while the entry names the keeper's own process (`Note::applies_to`). A note that cannot be written is logged and dropped.

`Phase::down` and `Phase::sweep` (`phase/src/phase.rs`) both stop what a record names without a plan, because the record stores how to stop each process. `down` leaves a workspace volume `Running`, and `RunRecord::all_stopped` ignores workspace volumes, so `down` still removes the record. The only caller of `sweep` in the product is `Runs::forget_id` (`multiverse/src/runs/phased.rs`), which `mxv remove` and `mxv archive` reach through `Runs::forget`, and `mxv repair --orphans` reaches for a run record whose id no record holds.

## Proxy

`Proxy::sync` in `crates/multiverse/src/proxy.rs` is the one entry point. It holds a lock in the proxy state directory, rebuilds the routes from the workspace records, reads the configuration that Caddy holds from its admin socket, and loads the new one only when the two differ. It returns early when no workspace declares a route and Caddy does not run. Caddy runs as a phase app of the workspace `mxv-proxy`. Caddy's own autosave is off (`persist` is false). `load` writes the loaded configuration to `bootstrap.json` in the proxy state directory, and phase's keeper restarts a killed Caddy from that file, so it serves the last load again at once. The next `sync` compares what Caddy holds with the current routes and loads only when they differ. `mxv proxy stop` stops the app and keeps the state. A sync that fails after a unit change leaves the units as they are and reports a warning.

## Port ledger

Ports are the `ports` map of the workspace record. A port is free or held. `.ports.lock` guards allocation (`Runs::assign_ports`, `multiverse/src/runs.rs`).

Four functions change the map. `Runs::assign_ports` allocates and drops. `ports_after_add` (`multiverse/src/workspaces.rs`) keeps and renames ports during `add`, and takes no port lock, because it allocates nothing. `Runs::restored_ports` replaces ports that are taken during a restore. `Runs::reset_ports` clears named ports and calls `assign_ports`.

| Transition | Owner | Crash point | State left | Recovery | Fault test |
| --- | --- | --- | --- | --- | --- |
| Free to held | `Runs::assign_ports` | The process dies after allocation and before `Store::update`. | Nothing is written. The lock is released. | The next `up` or `mxv run` allocates again. | None |
| Held to free | `Runs::assign_ports`, when the manifest no longer names a port and no process holds it | The process dies before the write. | The old map stays. | The next `up` drops it. | None |
| Held, renamed during `add` | `ports_after_add`, `Workspaces::finish_add` | The step fails. | `undo_add` restores the record. | The earlier map is back. | None. `a_failed_add_deletes_the_new_clone_and_restores_the_record` in `multiverse/src/workspaces/multi_tests.rs` fails earlier, before `ports_after_add` runs, and asserts nothing about ports. |
| Held, replaced during restore | `Runs::restored_ports` | The process dies during the call. | No record exists yet, and the rebuild table above applies. | The rebuild table above applies. | None |
| Held, after the record was deleted | `Runs::assign_ports`, through `Store::update` | None. `Store::update` returns `Error::RecordMissing` and writes nothing. | No record, so no port is held. | `mxv list`. | None. `up`, `restart`, `ports reset`, `exec` and `run` stop at `Context::lock` before they allocate, which `an_up_that_waited_for_the_lock_starts_nothing_when_the_record_was_deleted` in `mxv/tests/processes.rs` shows. |

A port is free when no workspace record holds it and a bind test passes. A workspace whose record survives keeps its ports whether or not it runs.

## Reclaim mark and pin

`Workspace.reclaimed` and `Workspace.pinned` are stored in the workspace record. `Reclaimed` holds the units that ran when reclaim stopped them.

| Transition | Owner | Crash point | State left | Recovery | Fault test |
| --- | --- | --- | --- | --- | --- |
| Running to reclaimed | `processes::reclaim_stop` (`mxv/src/processes.rs`) | The process dies after `stop_every` and before `Store::update`. | The units are stopped and no mark exists. | `mxv up` without names starts every unit of the manifest. The set that ran is lost. | None |
| Reclaimed to running | `Context::forget_reclaim` (`mxv/src/processes.rs`) | The process dies after the units start and before the write. | The mark stays. | The next `up` without names starts the marked set again. | None |
| Pin set or cleared | `processes::set_pinned` (`mxv/src/processes.rs`) | The write is atomic. | The old or new value is on disk. | Nothing needs recovery. | None |
| Running stays running, when the record went while reclaim waited for the lock | `processes::reclaim_stop` (`mxv/src/processes.rs`) returns the reason "the workspace's record was deleted while mxv waited for its lock" and stops nothing | None. | No mark and no record. | The row is `kept`, and reclaim carries on with the other workspaces. | `a_reclaim_that_waited_for_the_lock_keeps_a_workspace_whose_record_was_deleted` in `mxv/tests/reclaim.rs` deletes the record while the command waits and kills nothing. |
| Pin or unpin after the record was deleted | `processes::set_pinned` through `Context::lock` | None. | No record. | `mxv pin` and `mxv unpin` fail with `mxv::workspace::not_found`. | `a_pin_that_waited_for_the_lock_fails_and_writes_no_record_when_the_record_was_deleted` in `mxv/tests/processes.rs` deletes the record while the command waits and kills nothing. |

## Permission grants

A grant is the file `<phase state>/grants/<repository folder>-<16 hex digits>.json`, with the schema `phase/grants/v1`. Its states are absent, recorded and wider, which is recorded again with a larger set. No enum is stored, and the file's presence and content are the state. `grants::grant` (`phase/src/grants.rs`) holds a `flock` on `<file>.lock`, reads the file again under it, takes the union, and writes through phase's own temporary file, sync, rename and directory sync. Nothing else changes a grant. `mxv remove`, `mxv archive` and `mxv restore` do not touch it, because it belongs to the repository.

| Transition | Owner | Crash point | State left | Recovery | Fault test |
| --- | --- | --- | --- | --- | --- |
| Absent to recorded, or recorded to wider, on a person's yes | `Phase::grant`, called from `processes::ask_first` (`mxv/src/processes.rs`) before the workspace lock | The process dies before the rename. | The old grant, or none. | The next `up` asks again. | None |
| Same | Same | The process dies after the rename and before the build. | The new grant, with nothing built, stopped or started. | The next `up` finds no growth and starts without asking. | `a_grant_given_for_one_workspace_lets_another_workspace_of_the_repository_start` in `mxv/tests/processes.rs` plants the grant through the library and kills nothing. |
| Two grants at once | Two prompts answered yes, each through `Phase::grant` | Either holder dies. | One or both additions are on disk. | The missing addition asks again. | `two_concurrent_grants_keep_both_additions` in `phase/src/grants/tests.rs` runs two threads through the lock and kills nothing. |
| Any state to unreadable | Nothing writes it. `Phase::granted` detects a corrupt file or one from a newer phase. | Not applicable. | The file stays as it is. | `up`, `restart` and `exec` refuse with `phase::grants::unreadable` or `phase::grants::newer` until a person repairs or moves the file. | `a_corrupt_file_fails_with_its_own_code` and `a_newer_file_fails_with_its_own_code` in `phase/src/grants/tests.rs` plant the file and kill nothing. |
| Recorded to absent | A person moves the file away. | Not applicable. | Absent. | The next `up` asks about every selected host unit. | `a_scope_without_a_file_has_no_grants_and_asks_about_every_unit` in `phase/src/grants/tests.rs` plants the state and kills nothing. |

The check on `up` and `restart` stores nothing of its own. At a terminal it compares, asks and writes the grant on yes before the workspace lock. `Runs::build` then compares again under the lock, before any build step, and returns `BuildEnd::NotGranted` on growth, so a crash between the two leaves at most a grant and nothing built, stopped or started. `BuildsPassed`, which only `Runs::build` makes, is the only way into `Runs::up` and `processes::replace`. `a_unit_whose_permissions_no_person_granted_runs_no_build_and_asks_for_no_place` in `multiverse/src/runs/phased/build/tests.rs` and `a_manifest_that_widens_a_running_unit_is_refused_without_a_terminal_and_changes_nothing` in `mxv/tests/sandbox.rs` check that order.

`mxv down` with names adds no stored state. `Runs::down` computes the kept set from the status rows and the run record's `apps[].depends` while mxv holds the workspace lock, before `Phase::down`. A crash before `Phase::down` stops nothing, and a crash during it leaves the kept units running while the run record's `Stopping` row applies to the rest. `forget_reclaim` receives only the units that stopped, so a kept unit stays in the reclaim mark. `down_keeps_a_named_unit_that_a_running_unit_needs_and_stops_one_that_nothing_needs` in `mxv/tests/processes.rs` checks the kept set and kills nothing.

## Clean

`mxv clean` keeps no state, and `mxv reclaim --need disk` runs the same clean through `clean::run`. `clean_one` (`mxv/src/clean.rs`) holds the workspace lock, and `Workspaces::clean` (`multiverse/src/disk.rs`) measures again and calls `undeletable`. Before the pick, `hold_manifest_paths` keeps each path that only a repository's `mxv.toml` declares disposable, unless `clean --yes --disposable`, `reclaim --disposable` or a confirmed prompt lets the run delete it.

| Transition | Owner | Crash point | State left | Recovery | Fault test |
| --- | --- | --- | --- | --- | --- |
| Disposable directory to deleted | `clean_one`, `disk::tree::remove` (`multiverse/src/disk/tree.rs`) | Deletion fails or the process dies partway. | The directory is partly deleted. | The next `mxv clean` or `mxv reclaim --need disk` deletes the rest. | `a_path_that_cannot_be_deleted_in_full_fails_its_workspace_and_names_the_entry` in `mxv/tests/disk.rs` fails the step with an unwritable directory. |

## `mxv run`

`mxv run` keeps no state of its own. `Runs::prepare_task` (`multiverse/src/runs/phased/task.rs`) gives the workspace its ports under the workspace lock, as `up` does, and the lock ends before the task starts. The task runs through `Phase::exec`, which writes nothing to the run record, so `status`, `down` and `sweep` cannot find a running task. `archive`, `clean` and `reclaim` see it through the process table, as a process inside the workspace.

| Transition | Owner | Crash point | State left | Recovery | Fault test |
| --- | --- | --- | --- | --- | --- |
| Task running | `PreparedTask::run` (`multiverse/src/runs/phased/task.rs`) | `SIGINT` reaches `mxv` alone. | The task runs on and `mxv` waits for it. | `mxv` exits with the task's code. | `sigint_to_mxv_alone_leaves_the_task_running_and_mxv_ends_with_its_exit_code` in `mxv/tests/run.rs` sends the signal. |
| Task running | `PreparedTask::run` | `SIGTERM` or `SIGKILL` ends `mxv`. | The task runs on, and deadband frees its place, so the machine's job limiter no longer counts it. | Nothing recovers it. No record names the task. | None |

## Reports and configuration values

These enums have no stored state. Each is one of the following.

Computed afresh on each read:

- `multiverse::ProcessState` (`multiverse/src/runs.rs`) is mapped from phase's state on each status read.
- `phase::ProcessState` and `WorkspaceState` (`phase/src/status.rs`) are derived from the run record and the process table.
- `ContainerState` (`phase/src/engine/container/objects.rs`) is parsed from docker's answer.
- `Identity` (`phase/src/record/process.rs`) is computed when a process is examined.
- `CleanState` (`mxv/src/clean.rs`), `ReclaimState` and `Verdict` (`mxv/src/reclaim.rs`), and `BranchState`, `StateName` and `DirectoryFate` (`mxv/src/rows.rs`) are report rows.
- `Leftover` (`multiverse/src/workspaces.rs`) is computed on each `add`.

Results of one call:

- `UpOutcome` and `DownOutcome` (`multiverse/src/runs.rs`).
- `NewOutcome`, `AddOutcome`, `Fate`, `BranchFate`, `RemovalOutcome`, `RemovalPlan`, `CloneRefusal`, `Entry` and `Making` (`multiverse/src/workspaces.rs`).
- `Created` (`multiverse/src/store.rs`).
- `ArchivePlanned`, `ArchiveRefusal` (`multiverse/src/archive/admit.rs`), `ArchiveOutcome` (`multiverse/src/archive/retire.rs`), `RestorePlanned`, `RestoreRefusal` and `RestoreOutcome` (`multiverse/src/archive/restore.rs`).
- `SweepOutcome` (`phase/src/record.rs`), `AppOutcome` (`phase/src/report.rs`), and `AppStep`, `Step`, `Recorded` and `Begun` (`phase/src/engine/run.rs`).
- `KeeperExit` (`phase/src/engine/keeper.rs`) is an exit code.

Configuration values with no transitions:

- `Mode` (`multiverse/src/workspaces.rs`) selects a dry run or a change.
- `Need` (`mxv/src/reclaim.rs`) is parsed from the command line.
- `WorkspaceKind` (`multiverse/src/record.rs`) is set at creation and never changes.
- `Exit`, `DependencyRun` and `VolumeLifetime` (`phase/src/record/run.rs`) are stored and have no transitions.
